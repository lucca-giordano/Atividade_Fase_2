Linguagem de desenho “Quadro” · da AST ao SVG

1. Gramática (EBNF) e AST

programa    → tela comando*
tela        → "quadro" NUM "por" NUM
comando     → reta | circulo | retangulo | camada
reta        → "reta" ponto "ate" ponto estilo?
circulo     → "circulo" ponto "raio" NUM estilo?
retangulo   → "retangulo" ponto "tamanho" NUM "por" NUM estilo?
ponto       → "(" NUM "," NUM ")"
estilo      → "[" ( atributo ( "," atributo )* )? "]"
atributo    → "contorno" ":" cor | "fundo" ":" cor | "espessura" ":" NUM
cor         → COR | HEX
camada      → "camada" modificador* "{" comando* "}"
modificador → "move" "(" NUM "," NUM ")" | "gira" "(" NUM ")"

Comentários começam com -- e vão até o fim da linha. NUM aceita inteiros e decimais, com sinal opcional (-12, 113.14). Todo nó que pode ter erro semântico (Tela, Reta, Circulo, Retangulo, Camada) guarda o campo linha, preenchido pelo parser com a linha da palavra-chave que inicia o nó.

verificar(ast) visita a tela e depois cada comando com uma função recursiva que desce em todas as camadas (inclusive aninhadas). Ela não para no primeiro erro: junta todos em [ { linha, mensagem } ].

5. Decisões de projeto

  • Padrões sempre explícitos: toda forma recebe os três atributos fill, stroke e stroke-width. O gerador parte dos padrões (none, black, 1) e aplica os atributos na ordem escrita, então o último atributo repetido vale. A reta também recebe fill="none", para manter a regra uniforme.
  • Estilo na AST como lista: o parser guarda os atributos em uma lista, na ordem em que foram escritos, sem resolver repetições. Quem decide que o último vale é o gerador. Assim a AST continua fiel ao programa.
  • Cores ficam como lexema na AST: a tradução para nome de cor do SVG (tabela acima) acontece só no gerador. A cor transparente vira none.
  • Camada sem modificadores: gera <g> sem o atributo transform (em vez de transform=""). Ela só agrupa os filhos, sem mudar as coordenadas. Uma camada vazia (camada { }) gera <g></g>, que é válido.
  • Modificadores na ordem escrita: cada modificador vira uma função de transformação, e elas são unidas por espaço na mesma ordem da AST (move → translate, gira → rotate, em graus e no sentido horário). Modificadores repetidos (gira(10) gira(20)) são todos mantidos.
  • Gerador recursivo: gerarNo(no, nivel) trata cada tipo de nó e, para a Camada, chama a si mesma em cada filho com nivel + 1, o que também indenta o SVG.
  • Valores negativos: a gramática aceita sinal em NUM (útil para coordenadas locais em torno de (0, 0)). Por isso as verificações usam <= 0: raio, largura e altura negativos também são erro semântico, com a mesma mensagem “maior que zero”.
  • Linha dos nós: é a linha da palavra-chave que abre o nó (quadro, circulo, retangulo…), tirada do token pelo parser.
  • Ordem das fases: respeitada pelo main.js. Com erro semântico, gerarSVG não é chamado.
